# Evolve for Android

Packages the [Evolve](https://github.com/pmotschmann/Evolve) idle game as an installable Android
app, with a mobile-first redesign of its UI (touch-sized buttons, a pull-up drawer for resources,
tap-and-hold info popups, and more).

See [NOTICE.md](NOTICE.md) for licensing. Evolve is MPL-2.0. This wrapper's own code is licensed
separately.

## Layout

```
game/                     The game itself: HTML, CSS, and JS.
game/src/                 Hand-written source.
game/evolve/, game/wiki/  Built output, generated from game/src/. Don't edit these directly.
android/                  The native Android project, generated by Capacitor.
capacitor.config.json     Capacitor's config. Points at game/ for the web content to package.
package.json              The wrapper's own npm project (Capacitor and its plugins).
```

`game/` started as a clone of pmotschmann/Evolve and now includes a mobile UI redesign built on top
of it. See "Mobile UI architecture" below for how that's organized. Always rebuild `game/evolve/`
and `game/wiki/` after changing anything in `game/src/`.

## How it works

Capacitor wraps `game/` in a WebView and packages it as a real Android app. It works offline, has no
browser controls, and gets its own launcher icon.

Two Capacitor plugins add features the game didn't have in a browser:

- **Filesystem** and **Share** let Settings' "Save as File" button actually save the file on your
  phone, using Android's native share sheet so you can pick where it goes (Files, Drive, a messaging
  app, and so on).

The app relies on Evolve's own built-in catch-up system for time spent away. If Android suspends or
closes the app, Evolve fast-forwards your progress the next time you open it, the same way the
browser version already does when a tab is closed or backgrounded. There's no separate
background-running feature built into this wrapper.

## Mobile UI architecture

There's no separate "mobile build." One JS bundle and one CSS file ship for every platform. Mobile
behavior turns on at runtime, in two different ways:

- **Layout and CSS.** Almost all of it lives inside one `@media (max-width: 48rem)` block near the
  end of `game/src/evolve.less` (about a quarter of that file at this point). It only depends on how
  wide the screen is, so it also turns on if someone shrinks a desktop browser window narrow enough.
  It has nothing to do with being inside the Android app specifically.
- **Touch-specific JS behavior** (tap-and-hold on action buttons, stepper button glyphs, and so on)
  is gated by `isTouchInterface()` in `game/src/functions.js`. It checks for touch support, a mobile
  user agent, and a "Touch Device" setting the user can toggle in Settings. `game/src/vars.js` turns
  that setting on automatically whenever `window.Capacitor` exists, so the packaged app gets it
  without extra work, but the check itself is generic and has nothing to do with Capacitor.

In practice this means CSS changes are always safe to make broadly. They can't affect desktop layout
outside the media query. JS changes to shared functions like `setAction()` or `popover()` affect
both desktop and mobile callers, so a touch-only change needs its own `isTouchInterface()` check
rather than assuming the whole function is mobile-only.

For a list of non-obvious framework behavior we ran into while building this, see
[GOTCHAS.md](GOTCHAS.md).

## Building

Prerequisites (all CLI-only, no Android Studio GUI required):

- **JDK 21** (Temurin). This Capacitor version's Android libraries target Java 21. JDK 17 fails the
  build with `invalid source release: 21`.
- **Android SDK**, command-line tools only: `platform-tools`, `platforms;android-36`,
  `build-tools;36.0.0` (Gradle also pulls in `build-tools;35.0.0` on its own).
- `JAVA_HOME`, `ANDROID_HOME`, and `ANDROID_SDK_ROOT` set and on `PATH`. A shell that was already
  open when you set these won't see them until it's restarted.
- `android/local.properties` (not tracked in git, specific to your machine) points Gradle at the
  SDK, for example `sdk.dir=C:/Android`. Use forward slashes even on Windows. A backslash path
  breaks the Java compiler step.

```bash
# 1. Install the wrapper's own dependencies (Capacitor and its plugins), from the repo root
npm install

# 2. Install the game's build dependencies (esbuild, lessc, csso). Separate package.json,
#    separate install.
cd game
npm install

# 3. Build the game: game/src/*.js -> game/evolve/main.js (esbuild),
#    game/src/*.less -> game/evolve/*.css (lessc + csso), and the same for game/wiki/.
#    Run this again after every change under game/src/.
npm run build-win        # Windows. Use `npm run build` on macOS/Linux.
cd ..

# 4. Copy game/'s built output into the native Android project, and register any
#    Capacitor plugins. Only needs to run again when a native plugin changes, but
#    it's harmless to run every time.
npx cap sync android

# 5. Build the APK
cd android
./gradlew assembleDebug   # -> android/app/build/outputs/apk/debug/app-debug.apk
```

To install it on a phone: enable Developer Options and USB debugging, plug in via USB, then either
run `adb install app-debug.apk` or copy the APK over and open it directly (you'll need to allow
"install unknown apps" for whichever app you use to transfer it).

### Iterating without a phone

For CSS and layout work, a real device isn't necessary every round.

1. Temporarily add `<script>window.Capacitor = {};</script>` to `game/index.html`, right before the
   `evolve/main.js` script tag. This turns on the touch-only code paths, so a normal desktop browser
   behaves like the app does. Never commit this. It's a dev-only trick for testing.
2. Serve `game/` locally (`npm run serve` inside `game/`, or point any static file server at it) and
   open it in a browser at a narrow (48rem or less) viewport width, or with dev tools device
   emulation on.
3. To test against real game state instead of a fresh save, put an exported save file somewhere
   `game/` serves it from and import it from the console: `window.importGame(saveString, false)`.
4. Before committing, remove the `window.Capacitor` line from `index.html` and delete any temp save
   file. Neither belongs in the repo.

Whenever you move to a real APK build, don't skip steps 3 and 4 above (`npm run build-win` then
`npx cap sync android`) just because the last build still worked. Gradle packages whatever is
already sitting in `game/evolve/` and `game/wiki/`. It has no way to know those are out of date.
