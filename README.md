# Evolve — Android Wrapper

Turns [Evolve](https://github.com/pmotschmann/Evolve) (an incremental/idle browser game) into
an installable Android app, so it doesn't need a browser tab held open to make progress.

See [`NOTICE.md`](NOTICE.md) for licensing (Evolve is MPL-2.0; this wrapper's own code is separate).

## Layout

```
game/          Unmodified clone of pmotschmann/Evolve (the actual game: HTML/CSS/JS)
android/       Native Android project, generated by Capacitor (`npx cap add android`)
capacitor.config.json   Capacitor config — webDir points at game/
package.json   Wrapper-level npm project (Capacitor CLI + core deps)
```

## How it works

Capacitor packages `game/` as local static assets inside a WebView-based Android app — no
network connection required at runtime, no browser chrome, and it gets a real launcher icon.

### "Runs in the background" — how this is actually handled

Evolve already has a **built-in offline/catch-up system** (`addATime` / `exceededATimeThreshold`
in `game/src/functions.js`): if more than 120 seconds pass between ticks, it detects the gap next
time it runs and fast-forwards progress (at a reduced 2/3 rate, capped). This is the same mechanism
the browser version uses when you leave the tab in the background or close it entirely.

That means the default, low-effort, battery-friendly setup is: **let Android suspend/kill the app
like it does any other app**, and rely on Evolve's own catch-up math when it's reopened — no
persistent notification, no foreground service, no battery-optimization exemption needed. This is
how most successful idle-game Android ports behave, and is the recommended starting point.

If we later want literal live ticking while the screen is off (not just catch-up-on-reopen), the
next step would be a foreground service hosting a headless WebView/JS engine with a wake lock and
a persistent notification — more battery cost and more Play Store scrutiny, so treat it as a v2
option, not the default.

## Building

Installed on this machine (CLI-only, no Android Studio GUI):

- **JDK 21** (Temurin) — `C:\Program Files\Eclipse Adoptium\jdk-21.0.12.8-hotspot` — required
  because this Capacitor version's Android libs target Java 21 (JDK 17 fails the build with
  `invalid source release: 21`).
- **Android SDK**, command-line tools only, at `C:\Android`: `platform-tools`, `platforms;android-36`,
  `build-tools;36.0.0` (Gradle auto-pulled `build-tools;35.0.0` too, as a transitive requirement).
- `JAVA_HOME`, `ANDROID_HOME`, `ANDROID_SDK_ROOT`, and `PATH` are set at the Windows **user**
  environment level (persist across terminal sessions, but a *new* shell needs to pick them up —
  already-open shells won't see them until restarted).
- `android/local.properties` (gitignored, machine-specific) points Gradle at `C:/Android`
  — **use forward slashes**, a literal `sdk.dir=C:\Android` breaks the Java compiler step.

```bash
npm install                          # install Capacitor deps (already done)
npx cap sync android                 # re-copy game/ into the native project after any change to game/
cd android && ./gradlew assembleDebug   # builds android/app/build/outputs/apk/debug/app-debug.apk
```

No Android Studio GUI is installed — builds run from the terminal via Gradle. Install Android
Studio separately if you want the visual editor/emulator/logcat tools; it's optional for building.

To run it: enable Developer Options + USB debugging on your phone, plug in via USB, then either
`adb install app-debug.apk` or just copy the APK over and open it (you'll need to allow
"install unknown apps" for whatever app you copy it via).
